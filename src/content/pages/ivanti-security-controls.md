## FAQ

<details><summary>What are patch management tools?</summary>

These include software tools that automate the process of updating computer systems to their latest versions, reducing security risks and labor time.

</details>

<details><summary>What is the best patch management software?</summary>

There are dozens of patch management tools available. It is recommended that you choose tools that integrate quickly with your existing systems, making them easier for your IT workers to manage.

</details>

<details><summary>What are common automation systems that are used for patch management?</summary>

Many exist for a variety of operating systems. Organizations can use systems that automate patching for just a single type of system (such as Windows) or a suite that scans for current patching needs and helps IT managers schedule all automated patches.

</details>

<details><summary>What is the patch management process?</summary>

Build a complete inventory of their IT assets and assess the level of security risk for each; set up a testing environment for new patches; have a security team test new patches; back up current systems; configure systems; implement patches that have passed; keep up with new patches; and document the process.

</details>

<details><summary>What is SCCM patching?</summary>

The System Center Configuration Manager (SCCM) is a software suite used for enterprise patch management of many Windows machines.

</details>

<details><summary>Why do we need patch management?</summary>

Because software updates and patches protect business systems from security threats, patch management is used to ensure that all vulnerable IT assets are protected in a timely way.

</details>

<details><summary>How often should you patch servers?</summary>

Organizations should scan continually for new patches, then apply them within 30 days.

</details>

<details><summary>What are the general steps for patch management?</summary>

Create a standardized process (or purchase a software suite that manages the process) to inventory all IT assets and security issues they may have; arrange patches in order of priority; bring every patch under a single system; and ensure every single device is patched (even mobile devices).

</details>

<details><summary>What is a patch deployment process?</summary>

This term refers to the multi-step process of implementing new patches or hotfixes for software.

</details>

<details><summary>Why is an enterprise patch management system important?</summary>

Some organizations have a very large number of connected IT software, hardware, and network assets. Ensuring they are all protected from threats requires a standardized and well-tested enterprise patch management system.

</details>

<details><summary>Who is responsible for patch management?</summary>

IT system administrators should monitor the availability of software updates and patches, although other employees can also track patch information sources. System administrators should then test and install patches, using patch management tools.

</details>

<details><summary>What is the purpose of patch management?</summary>

Patch management is used to keep adequate control over downloading, testing, and installing many software updates (patches) across an entire organization, affecting many systems and IT assets. It ensures that each asset is protected by appropriate software patches.

</details>

<details><summary>Why is patching so important?</summary>

Software patches can protect IT assets from known security threats, while other patches improve or expand software functionality.

</details>

<details><summary>How often should patch management be performed?</summary>

Patch management should be used any time critical new patches are released. Organizations need a system for reliably monitoring information sources to detect patches that affect their IT assets.

</details>

<details><summary>How do you patch a server?</summary>

Organizations with multiple servers often use patch management tools to patch all of them simultaneously. Tools scan servers, identify missing patches, download patches, and install them.

</details>

<details><summary>How do you audit a patch management process?</summary>

Keep careful records of your current patch management process, then check it against best practices for patch management. Compile your networked assets; decide on patching priorities; and write a patch management policy that can be audited.

</details>
